## Long-term Knowledge

### Architecture

<!-- lore:019fa885-826f-7b8b-9b67-489f70a566c8 -->
* **Claude Explorer local-only data processing**: All user data (conversations, projects, users) is processed entirely on the local machine. The application reads from local JSON exports (users.json, conversations.json, projects.json) and stores auth credentials in ~/.claude-explorer/auth.json. No data is transmitted to external servers during parsing, indexing, or search operations. The web UI runs locally on localhost:3000 and serves only static assets plus API responses generated from local data. This architecture ensures privacy by design—data never leaves the user's device.

### Gotcha

<!-- lore:019fa897-7821-777e-b08d-3d3b5d96b81e -->
* **multer@2.0.2 breaks npm install**: Trap: \`npm install\` fails or hangs due to compatibility issues with \`multer@^2.0.2\` in package.json. It looks like a standard dependency but causes installation errors on some environments. Fix: Downgrade multer to \`1.4.5-lts.1\` if install fails. This version is stable and compatible with the existing Express setup without requiring Node version upgrades or complex workarounds.

<!-- lore:019fa8af-b4fe-76e9-827f-52bf61e5063e -->
* **server crash on missing conversations.json**: Trap: Server crashes with ENOENT error on startup if \`conversations.json\` is missing, preventing access to the UI upload feature. This looks like a standard file dependency but blocks the bootstrap flow. Fix: Updated \`src/web/server.ts\` \`initializeData()\` to catch load errors, log a warning, and initialize empty indexer/filter engines. This allows the server to start and serve the UI for data upload.

<!-- lore:019fa897-782a-7a23-816a-46a1e02cf651 -->
* **ZIP upload requires conversations.json root**: Trap: Uploading a ZIP file via the web UI fails with 'Missing required files' even if the archive contains valid data. This happens because the parser expects \`conversations.json\`, \`projects.json\`, and \`users.json\` at the root of the extracted directory, not nested in subfolders. Fix: Ensure the ZIP structure places these three JSON files at the top level. The server validates this specific flat structure before processing.

### Pattern

<!-- lore:019fa897-7831-7331-a2e7-82d69d5ddf53 -->
* **dev vs web server startup sequence**: Steps: 1. Run \`npm run dev\` in one terminal — starts \`tsc --watch\` for TypeScript compilation. 2. Run \`npm run web\` in a separate terminal — starts the Express server on port 3000. Gotchas: - Running only \`npm run dev\` does not start the server; it only compiles code. The app will not be accessible until \`npm run web\` is executed. - Server crashes on startup if \`conversations.json\` is missing at root. Fix: Modified \`src/web/server.ts\` to catch parse errors, initialize empty state, and allow UI upload instead of crashing. Verify: - \[ ] \`tsc --watch\` shows no compilation errors. - \[ ] Server logs 'Listening on http://localhost:3000' even without data files.
